> 用途：**原型 → 正式开发的对接依据**。原型全部走 `utils/api.js` 内存态；本文把每个函数翻译成 REST 端点、字段与错误约定，
> 后端按此实现后，页面侧只需把 `utils/api.js` 换成 fetch 封装，**页面代码零改动**。

## 一、总则

### 1.1 基础约定

| 项 | 值 | 说明 |
|---|---|---|
| Base URL | `/api/v2` | 网关统一前缀 |
| 协议 | HTTPS + JSON | `Content-Type: application/json;charset=UTF-8` |
| 认证 | `Authorization: Bearer <token>` | 登录态由网关维持；原型用顶栏角色切换模拟 |
| 时间格式 | `YYYY-MM-DD HH:mm:ss` | 日期字段 `YYYY-MM-DD`；金额单位**分**（见 1.5） |
| 时区 | `Asia/Shanghai` (+08:00) | 服务端统一按东八区落库 |

### 1.2 统一响应结构

所有接口返回同一信封，页面只用关心 `code === 0`：

```jsonc
// 成功
{ "code": 0, "message": "ok", "data": { } }

// 失败
{ "code": 40001, "message": "手机号格式不正确", "data": null, "traceId": "b7f3c1a2" }
```

> 原型的 reject 分支用 `Error` + `.code` 模拟（`utils/api.js` 的 `delay()`），
> 页面已有 `try/catch → ElMessage.error(e.message)` 链路，替换后行为一致。

### 1.3 分页约定（34 个列表接口统一）

原型签名：`queryXxx({ pageNo = 1, size = 20, filters = {} })` → `{ rows, total }`

```http
GET /api/v2/houses?pageNo=1&size=20&communityId=P01&kw=0101
```

```jsonc
{
  "code": 0,
  "data": {
    "rows": [ /* 实体对象，字段同 mock，见第三节 */ ],
    "total": 736,          // 符合条件的总条数，非本页条数
    "pageNo": 1,
    "size": 20
  }
}
```

- `size` 取值域：**20 / 50 / 100**（`PAGE_SIZES`），越界按 20 处理
- `pageNo` 从 **1** 开始；越界返回空 `rows` 且 `total` 不变
- **排序**：列表接口统一支持 `sortBy` + `sortOrder=asc|desc`，默认按实体主业务时间倒序
  （如房屋按 `houseId`、账单按 `createTime`、工单按 `createTime`）。原型未暴露排序参数，属新增能力。

### 1.4 筛选约定（三种原语，全站一致）

| 原语 | 原型实现 | HTTP 表达 | 语义 |
|---|---|---|---|
| 等值 `eq` | `eq(row, v, key)` | `?communityId=P01` | 空值/空串**跳过该条件**，不做强制过滤 |
| 关键字 `kwHit` | `kwHit(row, kw, keys, extra)` | `?kw=0101` | 对**指定字段集合**做包含匹配（大小写不敏感），命中任一即通过；`extra` 用于拼接主表没有的关联字段（如业主姓名） |
| 区间 `between` | `between(v, range)` | `?startDate=2026-10-01&endDate=2026-10-31` | 任一端为空则跳过；闭区间 |

组合条件之间是 **AND**。原型里每个 `queryXxx` 的 `filters` 键名即查询参数名，逐域列在第三节。

### 1.5 金额口径

- 传输单位：**分**（整数）。原型 mock 用的是元（如 `amount: 128.5`），对接时后端统一转分，
  页面 `utils/format.js` 的 `money()` 已按元展示，**不要改页面**。
- 计算精度：服务端用整数分运算，避免浮点误差；折扣/减免在服务端落库时不回写原单 `payable`，
  只写 `discount` 字段（原型即此口径，Q1 的收缴率分母依赖它）。

### 1.6 错误码

| code | HTTP | 场景 | 页面表现 |
|---:|---|---|---|
| 0 | 200 | 成功 | — |
| 40000 | 400 | 参数校验失败 | `ElMessage.error( message )`，表单项标红 |
| 40001 | 400 | 业务规则拦截（如「该告警已生成工单」） | 同上 |
| 40101 | 401 | 登录过期 / token 失效 | 跳登录页 |
| 40301 | 403 | 无权限（页面级或数据范围外） | 跳 403 页 |
| 40401 | 404 | 实体不存在 | 「记录不存在或已删除」 |
| 40901 | 409 | 状态冲突（如「合同已有变更在审批中」） | 提示后刷新列表 |
| 42201 | 422 | 导入文件解析失败 | 导入向导失败明细 |
| 42901 | 429 | 导出任务并发超限（>3） | 「已有 3 个任务在生成，请稍后」 |
| 50000 | 500 | 服务端异常 | 跳 500 页，附 `traceId` |
| 50400 | 504 | 超时 | 「请求超时，请稍后重试」 |

> 原型 `setFailMode()` 注入的四种异常（timeout/server/denied/expired）即对应上表 504/500/403/401，
> 用于 `/shell/states` 演示。对接后保留同一组 code，前端异常态页面无需改动。

### 1.7 延迟与加载态

原型 `LATENCY = 180ms` 保证 loading 可见。真实接口无需模拟延迟；**保留 `useListQuery` 的 loading 分支**，
请求 < 200ms 时会出现「闪一下」，属可接受。

## 四、写操作约定

### 4.1 通用规则

| 规则 | 说明 |
|---|---|
| **ID 服务端生成** | `woId`/`billId`/`contractId` 等一律由服务端发号，客户端传的业务单号（`woNo`/`contractNo`）也由服务端按规则生成后返回。原型里 `nextXxxId()` / `XXX_SEQ` 的发号逻辑要搬到服务端 |
| **校验前置** | 业务规则（量程上限、状态机流转、重复合并）在服务端校验，失败返回 40001 + 中文 message。页面已具备 `catch → ElMessage.error` 链路 |
| **返回更新后的实体** | 所有写操作返回**落库后的完整对象**，页面用它刷新列表/抽屉，不做二次查询 |
| **部分成功回执** | 批量类（开票 / 批量改工单 / 合并）返回 `{ok, failed[{id, reason}]}`，页面按「成功 N / 失败 M」展示 |
| **幂等键** | 写操作请求头带 `Idempotency-Key: <uuid>`，服务端 10 分钟内同键返回首次结果。防重复提交（原型无此问题，真实网络必须有） |

### 4.2 状态机（服务端必须强制执行）

```
工单    待派单 → 已派单 → 处理中 → 待确认 → 已关闭
                                  └→ 已取消（仅待派单/已派单可取消）
账单    未缴 / 部分缴费 → 已缴 ；逾期为未缴的衍生态（overdueDays>0）
        已作废、已减免 为终态，不再参与收缴率分母（Q1 口径）
票据    待开具 → 已开具 → 已红冲（终态）
审批单  待审批 → 审批中 → 已通过 / 已驳回 / 已撤回
合同    草稿 → 待审批 → 待生效 → 履行中 → 已终止 / 已到期
        变更中（changePending）不可再发起新变更 → 40901
押金    待收取 → 已收取 → 验收中 → 已退款 / 已扣款
告警    未处理 → 处理中 → 已处理；已生成工单不可再转 → 40001
```

### 4.3 内存态 → 持久化映射

原型所有写操作只改内存（刷新还原）。对接时按下表落地：

| 原型机制 | 正式实现 |
|---|---|
| `owners.push(...)` / `contracts.push(...)` | `INSERT` + 返回完整行 |
| `o.houseIds = o.houseIds.filter(...)` | 关系表 `owner_house` 增删 |
| `c._merged = true` | 软删：`status='已合并'` + `merged_into` 字段，不物理删除 |
| `EMP_ROLE_OVERRIDE` Map | `employee.role_id` 字段直接更新（原型的「覆盖」是因为员工角色由岗位反推） |
| `TENANT_REMIND` Map | `tenant_auth_remind` 表，一条租户一行存最近提醒时间 |
| `CONTRACT_CHANGE_ROWS` | `contract_change` 表，`status` 与审批单联动 |
| `WO_ROWS` / `OWNER_ROWS` 等派生数组 | **服务端 JOIN 后返回**，前端不再维护派生层 |
| `_syncXxxRow()` | 不再需要（派生逻辑移到服务端）——这是对接后可以删掉的一整类代码 |

## 五、横切能力契约

### 5.1 导出与下载中心（异步任务）

原型：`utils/export.js` + `utils/download.js`。页面只「提交任务」，文件在下载中心生成。

```
POST /api/v2/exports
{
  "name": "账单查询",          // 任务名
  "type": "列表",              // 列表 | 报表 | 导入模板 | 附件清单
  "source": "/b/bills",       // 来源路径，下载中心可跳回
  "filters": { ... },         // 提交时的筛选快照（服务端按此重算，保证与页面一致）
  "columns": [{"prop":"billId","label":"账单号"}],
  "format": "xlsx"            // Q6 已定
}
→ { "code":0, "data": { "taskId": "T20261023001" } }
```

任务状态机与查询：

| 方法 | 端点 | 说明 |
|---|---|---|
| GET | `/exports` | 任务列表（分页） |
| GET | `/exports/{taskId}` | 任务详情：`status` / `progress` / `size` / `error` |
| GET | `/exports/{taskId}/file` | 下载文件（`status=已完成` 才可用） |
| POST | `/exports/{taskId}/retry` | 失败重试 |
| DELETE | `/exports/{taskId}` | 删除任务 |
| DELETE | `/exports/finished` | 清空已完成 |

- 状态：`排队中 → 生成中 → 已完成 / 失败`
- **并发上限 3**（超出返回 42901）；条数 > 2000 时服务端应改为**后台生成 + 轮询**，不占满 HTTP 连接
- **有效期 24 小时**，过期后 `status=已过期`，文件不可下载
- **单次上限 5 万行**（Q6），超出返回 40000 并提示分批
- 文件名规范：`{name}_{YYYYMMDDHHmmss}.xlsx`

### 5.2 打印

原型：`utils/print.js`（`printHtml` / `printArea` / `docTable` / `docFoot`），三种单据：
催缴单、收款收据（含金额大写）、房屋台账。

正式实现保留同一套工具即可；若需服务端模板打印（固定格式、盖章），再增加：

```
POST /api/v2/print-templates/{templateKey}/render

```

### 5.3 导入向导

```
GET  /api/v2/imports/templates/{typeKey}    → { "name", "header", "sample": {...} }
POST /api/v2/imports                         → 上传文件 + typeKey
{ "code":0, "data": { "batchNo": "IMP...", "total": 200, "success": 195, "failed": 5,
                      "errors": [{"row":3,"field":"手机号","value":"1380013","reason":"..."}] } }
GET  /api/v2/imports/{batchNo}/errors        → 失败明细（可再导出）
```

## 六、权限与数据范围映射

### 6.1 页面级权限

- 权限位：`permissions.json` 50 个，结构 `{code, domain, domainName, func, funcName, op, opName, route}`
- 角色：`roles.json` 11 个，`perms[]` 挂权限位 code
- 页面守卫：菜单过滤 + 直访跳 403。对接后由**网关**按 token 解析角色做路由级校验，
  前端保留 `utils/rbac.js` 做菜单渲染（纯函数，无副作用）。

### 6.2 数据级权限（E4 五档，Q8 已定真正生效）

原型在数据层用 `scopeFilter()` 统一收口，**服务端必须实现等价逻辑**：

| 档位 | 过滤规则 |
|---|---|
| 全部项目 | 不过滤 |
| 指定项目 | `community_id IN (角色白名单)` |
| 本项目 | `community_id = 锚点员工所属项目` |
| 本部门 | `community_id IN (锚点部门及下级班组覆盖的项目)` |
| 仅本人 | 工单按 `assignee`、巡检任务按 `executor` 匹配锚点姓名；资产/费用类退化为按锚点项目收窄 |

- 服务端从 token 取角色 → 查角色 `dataScope` + `communities` → 解析锚点员工（该角色首位在职员工）
- **所有列表接口与汇总接口都要过这一层**，包括报表（Q7：沿用角色范围）
- 越权直访具体 ID：返回 40301，不要返回 40401（避免泄露存在性）

## 七、对接替换步骤

把原型切到真实后端，按这个顺序做，每步都可独立验证：

1. **写 fetch 封装**：新建 `src/utils/http.js`，实现 1.2 的信封解析、1.6 的错误码映射
   （`code !== 0 → throw Error(message, {code})`）、token 注入、401 跳登录。
2. **改造 `utils/api.js`**：保留**函数签名与返回结构不变**，把内部实现从内存过滤换成
   `http.get('/houses', { params })` / `http.post(...)`。这是唯一需要改的文件，页面零改动。
3. **删派生层**：`OWNER_ROWS` / `WO_ROWS` / `_syncXxxRow()` 等随服务端 JOIN 一起删除；
   `scopeFilter()` 换成服务端下发的 `X-Data-Scope` 响应头或直接由接口过滤。
4. **换下载中心**：`utils/download.js` 的 `build` 函数删掉，改调 5.1 的任务接口；
   轮询 `GET /exports/{taskId}` 刷新进度。
5. **保留异常态**：`/shell/states` 的四种注入改用真实错误码触发（断网/关权限），不要删。
6. **回归清单**：按 `未执行事项清单.md` 第十节的 7 批实测结论逐条复跑，
   重点校验数字自洽（Q1 收缴率 84.22%、应收−已收−未收=0）。
