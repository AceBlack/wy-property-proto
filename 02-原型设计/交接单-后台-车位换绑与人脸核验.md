## H2 · 车位与车辆：换绑记录改成真表

**现状（要修的）**：`/a/vehicles` 的换绑记录是 `parkingBindLogs(parking, vehicle)`
**现算出来的**（`03/src/utils/api.js:2761`），提交换绑只是往 `detailData.bindLogs` push 一条
（`03/src/views/a/VehicleList.vue:379`）。**刷新即丢**。

| 项 | 内容 |
|---|---|
| 数据 | `03/src/utils/api.js` 新增内存表 `parkingChangeLogs = []` + `addParkingChangeLog(rec)` / `parkingLogsOf(parkId)`；`parkingBindLogs()` 改为「真表记录 + 交付/授权两条派生说明」 |
| 字段 | `logId / parkId / parkNo / fromPlate / toPlate / source(业主自助｜物业代操作) / operatorName / vendorStatus(待同步｜已同步｜失败) / at / reason` |
| 页面 | `VehicleList.vue` 换绑记录区：加「来源」「厂商状态」两列；顶部给「本月已换 N 次 / 上限 M 次」；超限时给一个「重置本月次数」按钮（客服兜底，记一条操作日志） |
| 为什么 | 业主端已经能自助换绑了，后台看不见记录 = 出纠纷时无法举证；`vendorStatus` 恒「待同步」直到车牌识别系统接通 |
| 验收 | 后台换绑一次 → 记录出现且来源「物业代操作」；刷新后仍在；次数 +1；重置后次数归零并留痕 |

## H4 · 人脸核验（业主端提交后没人受理）

**现状（要修的）**：`03/src/views/a/OwnerForm.vue:88` 的「已录人脸」是一个手工开关
（`el-switch` 直接改 `faceRegistered`）。业主端提交人脸后**没有受理入口**，会永远停在「待核验」。

| 项 | 内容 |
|---|---|
| 页面 | 业主档案详情加一块「待核验人脸」：列表（业主本人 + 家庭成员）+ 缩略占位 + 提交时间 + 通过 / 驳回（驳回必填原因） |
| 状态机 | `未采集 → 待核验 → 已生效｜已驳回`；驳回必须带原因（业主端会展示给业主） |
| 数据 | `03/src/utils/api.js` 加 `faceRequests = []` + `submitFaceRequest / auditFaceRequest`；`owners.faceRegistered` 改为由「已生效」派生，不再手工开关 |
| 为什么 | 不补这一块，业主端的采集流程是断的：提交完没人审，永远刷不了脸 |
| 验收 | 造 3 条待核验（本人 / 配偶 / 子女）→ 通过 1 条 → 业主档案显示已录人脸；驳回 1 条并填原因 → 状态「已驳回」且原因可见；空原因被拦 |

> 原型阶段业主端的提交只落在浏览器 localStorage，后台看不到真实数据 ——
> H4 先做「工作台 + 状态机 + 样例数据」，等批次 83 接口化后自然接上。

## H5 · 租客人脸核验与 H4 合并同一入口

租客的人脸本来就有契约（`POST /tenants/{tenantId}/face`），但 PC 侧是散在租户编辑里的。

| 项 | 内容 |
|---|---|
| 做法 | 把「员工端/PC 提交的租客人脸」并入 H4 的同一个待核验工作台，按主体类型分两段：`业主与家庭成员` / `租客` |
| 为什么 | 同一件事两个入口，客服会问「到底在哪审」；租客与业主的核验标准也该一致 |
| 验收 | 工作台两段都有数据；通过/驳回对租客同样生效；租客列表里的 `faceRegistered` 跟着变 |
