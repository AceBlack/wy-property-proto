| 既有资产 | `screenshots/` 已有截图、`scripts/e2e/smoke.mjs` 已跑 puppeteer 冒烟 | 可直接升级为视觉基线 |

### 结论

**"效果一般"不是因为颜色不对，是因为 EP 组件的结构细节基本没被改过。**

Token 已经定好了"用什么色、多大圆角"，但 `el-table` 的密度、`el-card` 的分块、`el-tag` 的形态、`el-form` 的节奏、`el-menu` 的层级，全部还是 Element Plus 的默认结构。所以页面看起来"配色是我们的，骨架还是 EP 的"。

另一个隐性原因：`tokens.css` 头部写着视觉基调参考「站酷 SCRM 客户后台」。二手参考容易带出"通用 SaaS 模板感"——这也是需要换参考源的原因（见第五节）。

现在改一个表格行高，你只能凭感觉说"好像好点了"。做了基线之后，改完跑一次截图，能直接看出"间距变大了、密度降了、但行文字被截断了"。**没有基线，后面所有改造都是主观争论。**

复用已有 `puppeteer-core`，成本很低。

## 三、P1：先改这 6 个组件（按性价比排序）

| # | 组件 | 改什么 | 涉及 EP 变量 |
|---|---|---|---|
| 1 | **el-table** | 行高统一 48（可选 40 紧凑）、分隔线降到 `#f2f4f8` 级别、表头去底色只留字重、固定列阴影减弱 | `--el-table-border-color` `--el-table-header-bg-color` `--el-table-tr-bg-color` `--el-table-row-hover-bg-color` `--el-table-fixed-box-shadow` |
| 2 | **el-card / 页面区块** | 统一圆角 10 + 阴影 `--biz-shadow-card`、内边距 20/24、卡片头部与内容分离 | `--el-card-border-color` + 自定义类 |
| 3 | **el-tag** | 方块改胶囊（`--biz-radius-pill`）、统一到已有 StatusTag 的语义映射，禁止页面里直接写 el-tag | `--el-tag-*` |
| 4 | **el-form-item** | 标签宽度定值（不再随内容抖动）、行间距 20、错误提示位置固定 | `--el-form-*` |
| 5 | **el-menu** | 激活态改左侧指示条 + 浅底、二级缩进统一、hover 过渡 150ms | `--el-menu-*` |
| 6 | **el-skeleton / el-empty** | 统一收口到已有 `AsyncBlock` + `EmptyState`，禁止页面内裸用 el-empty | 组件替换，非样式 |

**纪律（比改造本身更重要）**：页面里不再直接写 `el-table` 的样式覆盖。所有覆盖集中在 `app.css` 一处。理由：EP 升级时覆盖会失效，集中一份只需查一个文件；散在 100 个页面里，升级等于重做。

## 四、P2：密度是"高级感"的最大变量

现在的 token 有颜色、圆角、阴影，**但缺密度**。这是后台视觉差异最直接的一项：

```css
/* 建议追加到 tokens.css */
--biz-density-compact: 40px;   /* 表格行高 · 数据密集页（账单、流水） */
--biz-density-default: 48px;   /* 默认 · 大多数列表 */
--biz-density-loose:   56px;   /* 卡片式列表、详情页 */
--biz-gap-module: 24px;        /* 模块间距（统一） */
--biz-pad-card: 20px;          /* 卡片内边距 */
--biz-content-max: 1440px;     /* 内容区最大宽度 */
```

三档密度对应三类页面，页面通过 `<el-table :row-style>` 或统一的 `density` 属性引用，**不写死数值**。

## 六、让后续设计更高效的四条协作机制

### 1. 先立一份「视觉意图」文件，替代形容词

在 `02-原型设计/` 建 `视觉意图.md`，写**可判定的参数**而不是"高级/大气/现代"：

- **密度**：三档行高、卡片内边距、模块间距的具体数值
- **克制度**：全站最多几个强调色；渐变只允许出现在哪（现在 `--biz-gradient` 存在，但要有使用边界）
- **圆角/阴影**：4 档各用在哪（卡片 / 弹层 / 控件 / 标签）
- **禁则**：不用什么——比"要什么"信息密度更高
- **锚点**：3 个"像它" + 3 个"不像它"，各带链接

我每次出方案前先读这份文件，风格就不会漂移。

### 2. 让我直接在你的工程里改，而不是给你图

我可以直接改 `tokens.css` / 加预览路由 / 跑截图对比。你看到的是**真实组件渲染**，不是设计稿——没有"设计稿落地走样"这一环，速度快 3 倍。

### 3. 建一个「对照页」代替来回描述

在 `src/views/shell/` 下加一个 `/shell/vision` 页面，同一组组件「改造前 / 改造后」并排。你只需说"要右边这个，圆角再小 2px"，比语言描述高效得多。这个页面还能当团队验收标准。

### 4. 每次只锁一件事

不说"整体提升质感"，说"这周只解决表格密度"。可验证、可交付、不返工。
