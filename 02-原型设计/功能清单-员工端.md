## 一、模块 A · 通讯录（PC 第 66 批）

**为什么要做**：一线最常问的是"这事找谁"。现在要打电话得回办公室翻 PC 员工档案，或问同事要号码。

| # | 功能 | 说明 | 依赖 | 待确认 | 验收 |
|---|---|---|---|---|---|
| **A1** 🟥 | 通讯录页 `pages/contacts/index` | 一屏：搜索框 + 部门 chips + 卡片列表。卡片 = 姓名 / 岗位 / 部门 / 手机（**明文**）+「复制」；点卡片弹「呼叫 / 复制」。不做部门树 | `@pc/utils/api` 的 `queryContacts({orgId,kw})` / `contactTree()` / `contactStats()`（已存在）；契约 `/contacts`、`/contacts/tree`、`/contacts/stats` **已有** | 无（口径已定） | 搜索姓名与手机后 4 位都能命中；切部门后列表变化；点号码能触发 `uni.makePhoneCall` |
| **A2** 🟥 | 两个入口 | ① 工作台宫格（与"巡检/工单"并列）；② 我的页列表项（排在"设置"上方）。**不占 tab** | 工作台 `modules` 已有装配逻辑；我的页 `selfEntries` 已有分组 | 入口文案用「通讯录」还是「同事电话」？（建议前者） | 两个入口都能进；周明（工程维修）也能看到 —— 通讯录 15 个角色都有 `c.contacts.view` |
| **A3** 🟥 | 数据层 `src/api/contacts.js` | 薄封装：按 `communityId` 归组、部门 chips 排序（本项目优先）、"已等/在线"这类派生字段**不要发明**。手机号**不脱敏** | A1 | 无 | 不直接读 `employees` 表；返回字段只有 7 个（empId/name/position/orgId/orgName/phone/gender） |

**为什么要做**：闲置先审后发、举报事后处置，这两件事都在"内容已经进了系统、等人拍板"的状态上，离开手机就卡住。

| # | 功能 | 说明 | 依赖 | 待确认 | 验收 |
|---|---|---|---|---|---|
| **B1** 🟥 | 邻里待办 `pages/neighbor/todo` | 两个分段：**待审核**（闲置）/ **待处理**（举报），各自计数；卡片带缩略图、发布人、**已等多久**（红黄分级） | `queryItems({filters:{status:'待审核'}})`、`queryReports({filters:{status:'待处理'}})`；权限 `n.items.view` + `n.reports.view` | 两个分段是否允许"一键全选处理"？（建议不做，逐条判断） | 默认显示本项目；待审 3 / 待处理 2（P01，以函数返回为准）；空态说明"别的项目还有单，不在你范围" |
| **B2** 🟥 | 闲置审核 `pages/neighbor/item` | 大图 + 描述 + 价格 + 发布人/楼栋（**不显示门牌**）；通过 / 驳回，**驳回必填理由**（预设 5 条 + 自定义） | `getItem(id)`、`auditItem(id,{pass,reason})`、`offlineItem`；权限 `n.items.audit` | 审核后是否要顺手"下架同发布人的其它违规内容"？（建议不做） | 驳回不填理由被拦；通过后列表少一条、PC 端状态同步（同一进程内） |

## 六、本轮的依赖关系

```
D1 契约 ─┬─> D2 mock-server
         └─> B/C 页面（HTTP 模式备用）

A1 通讯录 ──> A2 两个入口
              └─> A3 数据层

B1 待办 ──┬─> B2 闲置审核
          ├─> B3 举报处理
          └─> B4 工作台卡

C1 列表 ──┬─> C2 详情+代报名 ──┬─> C3 取消/退款
          │                    └─> C4 签到（P1）
          └─> 列表内就地代报名（共用 EnrollSheet 组件）

D3 自检 依赖以上全部
```

**先做 D1/D2 还是先做页面？** 建议先 A（通讯录，独立、0 风险）→ B → C，契约 D1 与 A 并行补。
理由：A 不依赖邻里数据，能立刻交付一个可用功能；B/C 的取数走函数，契约可以晚于页面两天。

## 七、明确不做（写进页面注释，防止顺手加）

1. 邻里**任何发布**：公告、投票、活动新建/编辑 —— 开了口子就会长成第二个后台。
2. **投票**全部页面（含结果查看）：没有现场动作，上去就是没人点的入口。
3. **确认流团（批量退款）**：一次点错是一批退款。
4. 报名名单**导出**、活动退款分档**配置**。
5. 通讯录的**编辑**（改岗位/手机）、**组织架构图**。
6. 临时收费 / 开票 / 收据打印（前台场景）。
7. 业主画像字段、租户换承租主体、租户批量核验（10-05 已确认不做）。
