## 二、清单（按「对开发的影响」排序，不按新旧）

### A. 数据与接口层 —— 这三条不做，前端没法开工

| # | 事项 | 为什么必须先做 | 优先级 |
|---|---|---|---|
| A1 | **用契约替换 mock**：按《接口层契约.md》先落 3 个高频域（业主/房屋、账单/缴费、工单） | 现在页面直接 `import` mock；接口一换，页面里所有 `filter/sort` 都要改成后端条件，越晚改越贵 | P0 |

## 四、需要先拍板的四件事

1. **派生字段归谁算**：后端物化（快、但要重算任务）还是查询时算（灵活、但慢且难对账）？
2. **业主/租户小程序是否与后台同仓**：决定接口要不要 BFF、鉴权怎么做。
3. **报表口径以谁为准**：现在报表与列表共用同一份派生函数；换成后端后，报表是走同一个接口还是独立 SQL？
4. **X5 乐观锁是否翻案**：原型判「不做」，但 A4 落地时绕不开，建议至少给"编辑冲突提示"。

---

## 五、不建议现在做的（避免浪费）

- 大屏 / 驾驶舱的进一步美化：口径没定之前，美化会返工。
- 更多报表：11 张已覆盖主要角色，缺的是"自定义"而不是"更多"。
- 全站换 UI 组件库：现有 Element Plus 已统一，换库成本远大于收益。

## 六、执行情况（2026-10-30 更新）

> 原则：能在前端闭环、且属于「口径正确性」的，全部落地；需要真实后端 / 支付通道 / 移动端容器的，标注原因不硬做——
> 硬做的结果通常是「页面上有个按钮，但业务上不成立」，评审时反而扣分。

| # | 事项 | 状态 | 落地方式 / 不做的原因 |
|---|---|---|---|
| A1 | 契约替换 3 个域 | ✅ 前端侧完成 | 新增 `src/api/`（client + 业主/账单/工单 + index）：`VITE_API_MODE=mock\|http` 同签名切换，页面改一行 import 即可**按域灰度**；服务端实现仍需后端 |
| A2 | 派生字段归属 | ✅ 部分 | 收口为 `billRow / _billHit / woSlaState / deptAchievement` 等**单一计算点**，并由 `/e/audit` 校验「应收=已收+未收」等不变量；归属仍需后端定（物化 or 查询算） |
| A3 | 枚举与字典收口 | ✅ | 新增 `utils/enums.js`（状态类从 `dict.js` 派生）+ `assertEnum`；`npm run check` 拦住 `部分缴费` / `进场` 这类历史分叉 |
| A4 | 唯一约束与乐观锁 | ✅ 前端模拟 | `assertUnique` / `checkVersion` / `bumpVersion`（409），业主手机号、在住租户证件号已生效 |
| A5 | 导出任务补强 | ✅ | 90s 硬超时回收、失败自动重试 1 次、进下载中心自动清理过期与 7 天前失败记录 |
| B1 | 数据范围下沉 | ✅ 前端模拟 | `assertInScope` 在取数入口抛 403（5 个高频查询已接），`useListQuery` 弹提示；真正下沉仍需后端 |
| B2 | 敏感字段服务端脱敏 | ✅ 前端模拟 | 列表只回掩码（`redactList`），明文走 `revealSensitive` 回源取并留痕；详情仍给明文（内联编辑依赖） |
| B3 | 访问日志不可篡改 | ✅ 前端模拟 | `sealLog` / `verifyLogChain` 哈希链，自检页实时校验；独立存储账号需后端 |
| B4 | 导出审批 | ⏸ 未做 | 需要审批流与审批人角色，属组织流程决策；现有「留痕 + 超限拦截 + 自动脱敏」先兜住风险 |
| B5 | 责任范围变更落库 | ⏸ 未做 | `STEWARD_LOG` 仍是内存；落库属后端，当前原型只演示留痕形态 |
| C1 | 收费对账 | ✅ 日结 + 退款冲红 | `/b/daily-close` 现金实点轧账、差异必填、一天一结锁定；退款冲回账单 + 已开票红冲；**支付回调幂等**需真实通道 |
| C2 | 通知触达 | ⏸ 未做 | 回执必须来自短信/微信通道，前端造「已读/失败」等于假数据，反而误导；模板与退订同属通道侧 |
| C3 | 工单 SLA | ✅ | 工作日历（9–18 点、跳周末节假日）、「待确认」停表、「已取消」不计、超时按日历算；**超时自动升级**属后端定时任务 |
| C4 | 巡检移动端 | ⏸ 未做 | 缺移动端容器（离线打卡、GPS 防作弊、照片水印），原型只有 1 个移动页，做离线队列没有落点 |
| C5 | 装修/访客/投诉闭环 | ⏸ 未做 | 需与押金、门禁授权联动，属产品口径决策；装修押金已单独立表，可作下一轮起点 |
| C6 | 自定义报表 | ⏸ 未做 | 需要「维度/指标元数据」设计，建议与后端报表引擎一起做 |
| D1 | 批量操作 | ✅ | 账单批量催缴 / 批量减免（原因必填）、租户批量核验（缺项按人回报）、工单批量改派优先 |
| D2 | 列设置 + 个人视图 | ⏸ 未做 | 需逐页把列定义抽成配置（8 个 B 型页约 90 列），属体验增强，排口径之后 |
| D3 | 空态 / 错误态覆盖 | ✅ 大部分 | 列表页统一 `EmptyState`；403 / 409 已冒成提示，不再是一张空表 |
| D4 | 键盘操作 | ⏸ 未做 | 收费岗收益真实，但需要先有「焦点管理 + 快捷键约定」，建议与列设置一批做 |
| D5 | 移动端 IA | ⏸ 未做 | 与 C4 同因：移动端整体尚未建，先定 IA 再谈页面 |
| E1 | 按域懒加载 | ⏸ 未做 | `utils/api.js` 的数据是**同步初始化**（模块顶层 `BILL_ROWS = bills.map(...)`），懒加载要把整个数据层改成异步初始化，影响所有页面——建议与 A1 后端对接一起做，那时数据本来就不是包内的 |
| E2 | 冒烟进 CI | ✅ 半自动 | `npm run check`（零依赖静态自检）+ `npm run verify`；puppeteer 冒烟脚本可挂 CI，但需要 Chrome 环境，暂留本地 |
| E3 | 环境与发布 | ✅ | `.env.example`（`VITE_API_MODE` / `VITE_API_BASE` / `VITE_APP_ENV`）；GitHub Pages 演示仍在（按你的要求**未再推送**） |
| E4 | 数据迁移工具 | ⏸ 未做 | 迁移工具依赖目标库结构，属后端交付物 |
| E5 | 埋点与可观测 | ✅ | `utils/track.js`（环形 300 条 + 本地持久化），已接导出 / 揭示 / 退款 / 日结 / 三个批量动作 |

### 一句话结论

**P0 里前端能做全做完了**（A1/A2/A3/B1/B2）；P1 的钱与时长也算对了（C1 日结退款、C3 SLA、A4/A5、D1）；剩下的都卡在
「需要后端 / 需要支付通道 / 需要移动端」三类硬约束上，属正常边界，不是欠账。
