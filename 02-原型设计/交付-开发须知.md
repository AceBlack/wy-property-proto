## 一、这套后台的页面骨架

已定型的标准列表页是**四段纵向结构**，从上到下：

```
┌─────────────────────────────────────────────────┐
│ 顶栏（60）· 项目切换 / 数据范围 / 角色            │  ← 全局，所有页共用
├─────────────────────────────────────────────────┤
│ 工具条（40）搜索 · 主筛选 · 快捷视图 · 更多筛选 · 操作 │  ← 页面第一行，没有标题行
├─────────────────────────────────────────────────┤
│ 更多筛选面板（可选展开，白底圆角 12）              │  ← 就地展开，不用弹层
├─────────────────────────────────────────────────┤
│ KPI 瓦片（4 个，白底圆角 14）                      │
├─────────────────────────────────────────────────┤
│ 范围小计行（30，单行）                            │
├─────────────────────────────────────────────────┤
│ 表格（行高 46，无卡片、铺在画布上）                │
├─────────────────────────────────────────────────┤
│ 分页（48）                                       │
└─────────────────────────────────────────────────┘
```

**三条硬约束：**

1. **没有页面标题行**。页面名在侧栏高亮和面包屑里，不需要再占一行（这一行曾占掉 34px + 间距，纯浪费）
2. **不用面包屑**。列表页直贴顶栏，用 `chrome: 'bleed'` 让内容出血（见第三节）
3. **表格不套卡片**。整页白底 + 浅灰画布，表格行直接铺在画布上

## 三、出血布局（`chrome: 'bleed'`）

列表页要顶到边，需要外壳配合。原型里的实现方式：

```js
// router/index.js —— meta 透传
meta: { ..., chrome: p.chrome || '' }

// pages.js —— 单页声明
{ path: '/b/bills', ..., chrome: 'bleed' }

// AppShell.vue —— 出血页不出面包屑、body 去掉内边距
const bleed = computed(() => route.meta?.chrome === 'bleed')
<div class="app-body" :class="{ 'is-bleed': bleed }">
<div v-if="!bleed" class="app-crumb">
```

```css
/* 列表页用 height:100% 自己管高度，不滚动；详情页内容更高，由 body 滚动 */
.app-body.is-bleed { padding: 0; overflow: auto; }
```

**为什么必须这么做**：不用出血的话，`.app-top(60) + .app-crumb(40+16) + .app-body padding(24)` = 140px 会被白白吃掉，页面只能用 `calc(100vh - 140px)` 猜高度——一旦外壳改尺寸，所有页面高度全错。**出血之后页面用 `height: 100%` 即可。**

## 四、避坑清单（这轮实际踩到的，正式开发会重踩）

### 4.1 布局

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 用 `calc(100vh - Npx)` 给页面定高 | 用 `chrome: 'bleed'` + `height: 100%`，让 flex 分配 |
| 2 | 表格用 `max-height` 导致分页压在表格上 | 表格容器 `flex:1; min-height:0; overflow:hidden`，表格 `height="100%"` |
| 3 | 容器不加约束导致内容溢出到屏幕外 | 每层 flex 子项都写 `min-height: 0` |
| 4 | 为了强调卡片加深页面底 | 页面底 `#F7F8FA` 与卡片 `#FFF` 只差 8 阶，够了 |

### 4.2 组件

| # | 坑 | 正确做法 |
|---|---|---|
| 5 | 筛选条件放弹层，遮住表格且要滚动 | 就地展开面板（160ms 动效），条件多时也不遮内容 |
| 6 | 表格套卡片，和画布形成双层框 | 表格透明底，铺在画布上，只留行分割线 |
| 7 | 状态用浅底胶囊，视觉很吵 | 圆点 + 文字 |
| 8 | `el-table` 内塞操作按钮导致横向溢出 | 点整行开详情，末列不放按钮 |

### 4.3 代码

| # | 坑 | 正确做法 |
|---|---|---|
| 9 | 用工具函数返回值时凭印象写字段名（写了 `b.name`，实际是 `b.label`）→ 渲染为空且不报错 | **先打印/读一遍返回结构**，再写模板 |
| 10 | 入口按钮对所有角色都渲染，无权限的人点了撞 403 | 权限判断放在**是否渲染**层（`v-if="canVisit(...)"`） |
| 11 | 切模板块时用 `indexOf('</template>')`，取到表格列里的内部 `</template>`，整块内容被切丢 | 切 SFC 用「最后一个 `</template>`」或按行号定位；改完必须 build |

### 4.4 判断方法

| # | 坑 | 正确做法 |
|---|---|---|
| 12 | 看缩略图判断「文字被裁切」，实际是缩放假象 | 判断裁切必须看 **1:1 裁剪图** |
| 13 | 凭肉眼判断「实现和效果图不一致」 | 同位置取 RGB 比对（差值 20 阶以上才是真问题） |
| 14 | dev server 长期挂着，沙箱进程死掉后报 500，被误认为代码错误 | 报 `execution attempt 不存在或已关闭` 时先重启服务 |

## 七、正式前端接入（Element Plus 栈，10 分钟）

```ts
// main.ts
import 'element-plus/dist/index.css'   // 1. 先引 EP 默认样式
import '@/styles/theme.css'            // 2. 再引交付主题（即 交付-theme.css）
```

```css
/* theme.css = 交付-theme.css 原样拷贝，不需要改一行 */
```

**三个必须知道的点：**

1. **顺序不能反**。EP 默认样式在后会把所有变量覆盖回去，表现为「主题完全没生效」。
2. **表格 / 分页 / 复选框的变量必须写在组件作用域**（`.el-table {}`），写在 `:root` 不生效——EP 在组件内部重定义了它们。`交付-theme.css` 已经处理好，别把它们合并进 `:root`。
3. **不要给 `--el-color-primary` 之外的按钮刷主色底**。需要排除 `is-plain / is-link / is-text` 三种变体，否则会出现「蓝底蓝字」的纯色块（原型踩过两次）。

非 Element Plus 栈（React + Ant Design / 自研组件）时：`交付-tokens.json` 直接导入构建流程，`交付-theme.css` 只作变量取值参考。
